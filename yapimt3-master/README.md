# Транслятор и Виртуальная Машина для С-подобного языка

Данный проект представляет собой полноценный учебный транслятор (компилятор + интерпретатор) для подмножества С-подобного языка программирования. Проект написан на C++ (стандарт C++17) и включает в себя лексический анализатор, нисходящий LL(1) синтаксический анализатор, модуль семантического контроля и стековую виртуальную машину для выполнения сгенерированного кода (ПОЛИЗ).

## 🚀 Основные возможности

*   **Полноценный пайплайн компиляции**: Исходный код -> Токены -> Семантический анализ -> ПОЛИЗ (Обратная польская запись) -> Исполнение на виртуальной машине.
*   **Восстановление после ошибок (Panic Mode)**: Лексический и синтаксический анализаторы не завершают работу при первой ошибке. Они переходят в режим "паники", синхронизируются по разделителям и продолжают анализ, позволяя найти максимум ошибок за один проход.
*   **Встроенные семантические проверки**: Парсер выявляет повторное объявление переменных, использование необъявленных переменных, изменение констант и несовпадение типов (например, присваивание `float` в `int`).
*   **Безопасное выполнение (Runtime Checks)**: Виртуальная машина перехватывает ошибки времени выполнения: выход за границы массива, работу с неинициализированными переменными, а также переполнение (Integer Overflow) и нехватку операндов в стеке.
*   **Интерактивное консольное меню**: Удобный интерфейс для пошаговой отладки таблиц, токенов, синтаксического дерева и запуска программы.

## 💻 Поддерживаемый язык программирования

Разработанный язык поддерживает строгие лексические и синтаксические конструкции:

### Типы данных и переменные
*   `int` — 32-битное знаковое целое число.
*   `float` — вещественное число двойной точности.
*   `array<int>`, `array<float>` — одномерные массивы фиксированной длины.
*   **Именованные константы** — идентификаторы, состоящие только из ЗАГЛАВНЫХ букв и `_`. Модификация после первого присваивания запрещена.
*   **Идентификаторы** — регистрозависимые имена, начинающиеся с буквы или `_`.

### Операции
*   **Арифметические**: `+`, `-`, `*`
*   **Сравнения**: `==`, `!=`, `<`, `>`
*   **Присваивание**: `=`
*   Доступ к элементам массива по индексу (например, `arr[2] = 5;`).
*   **Ввод данных**: поддерживается операция `read(id);` для чтения из внешнего источника.

### Комментарии
*   Однострочные: `// комментарий`
*   Многострочные: `/* многострочный комментарий */`

## 🏗 Архитектура проекта

Проект разделен на несколько независимых модулей:

### 1. Лексический анализатор (Scanner / Lexer)
**Файлы:** `lexer.cpp`, `lexer.h`, `lexertypes.cpp`, `lexertypes.h`
Читает исходный код из файла и преобразует его в поток токенов. Распознает идентификаторы, числа, ключевые слова и разделители на основе словарей конфигурации (`config/`).
Хранит все переменные в `VarTable` (хэш-таблица с открытой адресацией и квадратичным пробированием). Результат сохраняется в `output/tokens.txt`.

### 2. Синтаксический и семантический анализатор (Parser)
**Файлы:** `parser.cpp`, `parser.h`
Реализован в виде автомата с магазинной памятью (стеком), управляемого жестко заданной таблицей состояний (нисходящий LL(1)-разбор).
В процессе прохода парсер проверяет семантику (объявления, типы) и, если ошибок нет, переводит выражение из инфиксной формы в **ПОЛИЗ** (постфиксную форму). Сохраняет результат в `output/poliz.txt`, а трассировку переходов автомата в `output/trace.txt`.

### 3. Виртуальная машина (Interpreter)
**Файлы:** `interpreter.cpp`, `interpreter.h`
Стековая ВМ, которая последовательно считывает инструкции ПОЛИЗа и исполняет их. 

**Зачем нужна Виртуальная Машина, если есть семантический анализ?**
Семантический анализатор работает на этапе *компиляции* (статически). Он проверяет только то, что можно узнать до запуска кода: объявлена ли переменная, совпадают ли типы и константы. Однако многие ошибки возникают только в *рантайме* (во время выполнения), когда вычисляются конкретные значения. Виртуальная машина необходима для:
*   **Динамической проверки индексов массива:** В выражении `arr[i]` семантика проверит лишь то, что `i` — это целое число. И только ВМ при выполнении узнает, чему именно равно `i`, и предотвратит выход за границы.
*   **Контроля инициализации:** Семантика позволяет написать `int a; int b = a + 1;`, так как типы сходятся. Но ВМ в момент выполнения операции `+` увидит, что в `a` еще не положили значение, и безопасно остановит программу.
*   **Защиты от переполнения:** ВМ отслеживает, чтобы результат арифметических операций динамически не превысил лимиты 32-битного числа (`INT_MAX`/`INT_MIN`).
*   **Работы с внешними данными:** Команда `read()` получает данные из файла именно в момент выполнения. Семантика не может предсказать, что будет считано.

### 4. Вспомогательные структуры
**Файлы:** `tables.cpp`, `tables.h`, `utils.cpp`, `utils.h`
Описывают классы таблиц констант (`ConstTable`) для хранения алфавита и ключевых слов, а также таблицу переменных (`VarTable`), управляющую выделением памяти для массивов и сохранением состояний переменных.

## 📂 Структура директорий

```text
├── config/                  # Словари (алфавит, ключевые слова, разделители)
├── data/                    # Данные (сохраненные таблицы переменных и тестовые исходники)
├── output/                  # Сгенерированные артефакты (ошибки, токены, полиз)
├── CMakeLists.txt           # Скрипт сборки
├── main.cpp                 # Точка входа, реализация консольного меню
├── lexer.* / parser.*       # Исходные коды компонентов компилятора
├── interpreter.*            # Исходный код виртуальной машины
└── СТРУКТУРА.md             # Внутренняя техническая документация автора
```

## 🛠 Сборка и запуск

Проект использует систему сборки **CMake** (минимальная версия 3.10) и стандарт **C++17**.

### Сборка под Linux/macOS:
```bash
mkdir build
cd build
cmake ..
make
```

После успешной сборки запустите исполняемый файл:
```bash
./Lab3
```
*Примечание: При запуске файлы конфигурации (`config/`) и данные (`data/`) автоматически скопируются в директорию сборки, а также будет создана папка `output/`.*

## 🎮 Использование меню

При запуске программы открывается интерактивное меню из 15 пунктов:
*   `1-3`: Проверка символов на принадлежность алфавиту/разделителям/резервным словам.
*   `4-9`: Ручное управление таблицей лексем (добавление, поиск, изменение, удаление переменных).
*   `11`: Запуск только лексического сканера для выбранного файла (например, `Code7.cs`).
*   `12-13`: Просмотр сгенерированных токенов и найденных ошибок прямо в консоли.
*   `14`: Запуск синтаксического анализа (проверка грамматики и генерация ПОЛИЗ).
*   `15`: Полный цикл компиляции и исполнения: чтение исходного кода -> парсинг -> исполнение на виртуальной машине.
