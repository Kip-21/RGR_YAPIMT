СТРУКТУРА ТОКЕНА
Каждый распознанный элемент (токен) в программе представляется структурой Token:
•	type — категория токена (значение из перечисления TokenType).
•	index — индекс элемента в соответствующей таблице (постоянной или переменной).
•	line, col — позиция (строка и столбец) токена в исходном коде для удобства вывода и отладки.
Типы токенов (TokenType):
1 — SYMBOL
2 — OPERATION (Операции)
3 — KEYWORD (Ключевые слова)
4 — DELIMITER (Разделители)
5 — IDENTIFIER (Идентификаторы)
6 — NAMED_CONSTANT (Именованные константы)
7 — UNNAMED_CONSTANT (Числовые константы)
В файл результат выводится в виде последовательности пар (n, m), где n — тип токе-на, m — индекс в таблице.
СТРУКТУРА ТАБЛИЦ
Для работы транслятора спроектированы следующие типы данных:
ConstTable — Структура для хранения постоянных таблиц (алфавита, ключевых слов, разделителей). Использует контейнер set<string> для эффективного хранения и автоматиче-ского исключения дубликатов. Методы:
•	contains(const string& elem) — проверяет, содержится ли элемент в таблице.
•	getIndex(const string& elem) — возвращает порядковый индекс элемента (с помощью алгоритмов distance).
•	loadFromFile(const string& filePath) — загружает данные из текстового файла построч-но.
LexemeAttributes — Структура для хранения атрибутов переменных (идентификаторов или констант), включающая поля:
•	type — строковое представление типа переменной (int, float, array<int>, array<float> или "-" в случае, если тип еще не определён на этапе лексического анализа).
•	value — инициализируемое значение лексемы (или строковое представление вида "[val1, val2]" для массивов).
•	is_constant — флаг, указывающий, является ли лексема константой.
•	is_named — флаг для именованных констант (состоящих из заглавных букв и знаков подчеркивания _).
•	array_size — размер массива (количество зарезервированных элементов).
•	array_values — вектор строк std::vector<std::string>, содержащий отдельные значения элементов массива.
Методы:
•	updateArrayData() — вспомогательный метод для парсинга строкового представления массивов (например, из "[1, 2, 3]" извлекает элементы, убирает лишние пробелы и табуляции, инициализирует array_values и подсчитывает array_size).
VarTable — Таблица для хранения уникальных переменных (идентификаторов и число-вых констант). Реализует структуру хеш-таблицы (массив структур Entry) для эффективного поиска, вставки и удаления. Включает:
•	table_size — текущий размер таблицы (всегда поддерживается как простое число).
•	elements — количество активных элементов в таблице.
•	table — вектор структур Entry, где Entry хранит lexeme (имя), attributes (атрибуты), а также флаги occupied (занято ли место) и deleted (было ли удалено).
•	filename — имя файла для сохранения таблицы на диск (variables.txt).
•	reservedWords — объект ConstTable для проверки совпадений с резервированными словами. Основные методы:
•	insert(const string& lexeme, const LexemeAttributes& attributes) — вставляет лексему с проверкой корректности имени, типов и значений, автоматически расширяя таблицу (resize) при факторе загрузки > 0.5. Запись происходит на первое свободное либо "удаленное" место по хешу.
•	remove(const string& lexeme) — логическое удаление (место помечается фла-гом deleted=true).
•	update — изменение полей type и value существующей лексемы.
•	contains, getIndex, getAttributes — поиск элементов и извлечение данных.
•	saveToFile(), loadFromFile() — сериализация и десериализация хеш-таблицы в тексто-вый формат.
ХЕШИРОВАНИЕ И КОЛЛИЗИИ
Таблица переменных реализует хеш-таблицу с методом открытой адресации и квадратич-ным пробированием. Функции:
•	customHash – вычисляет хеш-код строки (полиномиальная хэш-функция).
•	rehash – выполняет квадратичное пробирование при коллизиях.
АЛГОРИТМ РАБОТЫ СКАНЕРА
Основой сканера является функция tokenizeFile. Алгоритм работы анализатора можно описать следующим образом:
Посимвольно считываем информацию из файла, пока не дойдем до конца файла (while (file.get(c))):
1.	Встаём в начальное состояние ДКА (START), обнуляем буфер и определяем следующее состояние ДКА на основе поданного символа, либо сразу фиксируем одиночные символы. 
2.	В цикле накапливаем символы: пока считываемый символ является продолжением те-кущей лексемы согласно ДКА (например, продолжаем в состоянии IN_ID или IN_NUMBER), мы обновляем буфер и переходим к следующему символу. c. Когда текущее состояние ДКА доходит до логического завершения (встречен пробел или безопасный разделитель), выпол-няется специальное действие processBuffer() для классификации и проверки буфера. 
3.	Если распознанная лексема соответствует одной из категорий (ключевое слово, валид-ный идентификатор, константа), то записываем полученный токен (с типом n и индексом m) в массив токенов и переводим состояние обратно в START. 
4.	Иначе (например, встречен неизвестный символ или недопустимая буква в числе), ДКА переходит в режим синхронизации PANIC, выводится сообщение об ошибке, и информация об ошибке с точной позицией записывается в файл.
ВЫБОР СТРАТЕГИИ РАЗБОРА
Для синтаксического анализа выбрана стратегия нисходящего LL(1) - разбора.
Причины выбора:
- грамматика языка небольшая;
- анализ выполняется слева направо;
- достаточно одного символа предпросмотра.
Принцип работы: 
Анализатор реализован как автомат с магазинной памятью (стеком), управляемый таблицей состояний.
На каждом шаге:
1.	Автомат сверяет текущий токен с направляющими символами (terminals). 
2.	При совпадении: выполняются действия согласно управляющим флагам: считывание токена (accept) , сохранение адреса возврата в стек (stack) , переход к другому состоянию (jump) или возврат по адресу из стека (return).  
3.	При несовпадении: автомат либо переходит к проверке следующей альтернативы , ли-бо, если установлен флаг error, выдает сообщение о синтаксической ошибке.  
ГРАММАТИКА ВХОДНОГО ЯЗЫКА
Исходная контекстно-свободная грамматика описывает подмножество языка C++, включающее типы int, float, массивы, операторы описания, присваивания и арифметико-логические выражения. Правила имеют вид: Нетерминал -> цепочка терминалов и нетерми-налов.
Терминальные символы (T): {int, float, id, const, =, +, -, *, ==, !=, <, >, [, ], ;, ,}. 
Нетерминальные символы (N): {Program, StmtList, Stmt, Type, DeclTail, Expr, RelOpTail, RelOp, SimpleExpr, AddOpTail, AddOp, Term, MulOpTail, Factor, ArrayElems, ArrayElemsTail}. 
Целевой символ: Program. 
Грамматика была приведена к виду, удобному для LL(1)-разбора.
Основные преобразования:
•	Устранение левой рекурсии
Классические правила для выражений вида E -> E + T заменены на праворекурсивные формы с использованием вспомогательных нетерминалов (суффиксов Tail), что позволяет парсеру не зацикливаться и корректно обрабатывать ассоциативность: 
SimpleExpr -> Term AddOpTail
AddOpTail -> AddOp Term AddOpTail | ε
•	Левая факторизация
Для правил, имеющих общие начальные цепочки, выполнена левая факторизация. Это позволяет анализатору выбирать нужное правило, глядя только на один текущий токен (L-предпросмотр). 
Пример: Описание переменной и присваивание разделены на уровне нетерминала Stmt. Если текущий токен — ключевое слово типа (int/float), выбирается ветка описания. Если текущий токен — идентификатор (id), выбирается ветка присваивания. 
•	Иерархия приоритетов
Для соблюдения математических приоритетов в синтаксическом анализаторе выражения искусственно разделены на иерархические уровни (вложенные нетерминалы).
В основе грамматики лежит правило: чем глубже уровень грамматического вызова, тем выше приоритет операции. 
Анализ выражения всегда начинается с операций низшего приоритета (например, сравне-ния или сложения), которые для своего завершения принудительно вызывают правила бо-лее глубокого уровня (например умножение). Такая структура гарантирует, что операции с высоким приоритетом будут полностью разобраны и перенесены в выходную постфиксную запись строго раньше низкоприоритетных, что обеспечивает синтаксически корректный порядок вычислений.

ОБРАБОТКА ОШИБОК И СИНХРОНИЗАЦИЯ (PANIC MODE)
Анализатор корректно обрабатывает лексические, синтаксические, семантические ошибки, а также ошибки времени выполнения (Runtime), предотвращая аварийное завершение работы транслятора и позволяя находить множественные проблемы за один проход:
1. **Лексические ошибки:**
   * При обнаружении некорректного символа или неверного числового формата сканер переходит в режим паники (**PANIC**).
   * Информация об ошибке (номер строки, столбца и точная лексема) записывается в `output/errors.txt`.
   * Автомат пропускает ошибочные символы до первого «безопасного разделителя» (пробел, перевод строки, операторы, точка с запятой `;` или круглые/квадратные скобки), после чего сбрасывает буфер ошибки и возвращается в состояние **START**.
2. **Синтаксические ошибки:**
   * При несовпадении текущего токена с направляющими символами строки с флагом `error=true` синтаксический анализатор фиксирует ошибку в `output/errors.txt` (с указанием расположения и неожиданного токена).
   * Включается режим паники синтаксического анализатора: токены пропускаются до тех пор, пока не встретится точка с запятой `;` (конец инструкции) или ключевое слово начала нового предложения (`int`, `float`). Стек автомата очищается, и разбор возобновляется со следующего оператора (состояние 3 — `StmtList`).
3. **Семантические ошибки:**
   * Выявляются и обрабатываются непосредственно синтаксическим анализатором (`SyntaxAnalyzer`) в процессе разбора токенов перед генерацией ПОЛИЗа (поскольку семантический анализ полностью совмещен с синтаксическим).
   * Сообщение об ошибке с точными координатами (строка и столбец) и причиной (например, `Semantic Error: Type mismatch, cannot assign float to int`) записывается в файл `output/errors.txt` синтаксическим анализатором.
   * Обнаружение хотя бы одной семантической ошибки взводит флаг ошибки в парсере, что блокирует последующий перевод программы в ПОЛИЗ и её запуск на виртуальной машине (пункт 15 меню не запустит программу).
4. **Ошибки времени выполнения (Runtime-ошибки):**
   * Возникают во время непосредственного выполнения сгенерированного ПОЛИЗа стековой виртуальной машиной (VM) в `interpreter.cpp`.
   * Виртуальная машина перехватывает эти сбои и выбрасывает исключение `std::runtime_error`, которое выводится пользователю на экран ярким красным цветом (например, `[RUNTIME ERROR] Runtime Error: Array index out of bounds`).
   * К ним относятся: выход за границы массива при доступе по индексу, попытка использовать неинициализированную переменную в вычислениях, целочисленное переполнение знакового типа при арифметике или недостаток элементов в стеке операндов.

РЕАЛИЗАЦИЯ ИНТЕРАКТИВНОГО МЕНЮ (main.cpp)
Главный цикл программы предоставляет пользователю 15 пунктов для всестороннего тестирования и пошаговой отладки транслятора:
1. **Check element in alphabet** — проверка символа на принадлежность алфавиту языка.
2. **Check element in reserved words** — проверка слова на зарезервированность.
3. **Check element in delimiters/operations** — проверка разделителя или знака операции.
4. **Add lexeme (identifier/constant)** — добавление новой лексемы в хэш-таблицу вручную.
5. **Check if lexeme exists** — проверка существования лексемы в хэш-таблице по имени.
6. **Get lexeme attributes** — извлечение типа и значения лексемы из `VarTable`.
7. **Print all lexemes** — вывод на экран всего текущего содержимого хэш-таблицы переменных.
8. **Delete lexeme** — удаление лексемы (помечается флагом `deleted=true` без физического сдвига).
9. **Update lexeme** — изменение типа и значения уже существующей переменной в хэш-таблице.
10. **Exit** — завершение работы приложения.
11. **Run Scanner on file** — запуск лексического сканера. Читает исходный текстовый файл, заполняет хэш-таблицу константами и идентификаторами, генерирует списки токенов в `output/tokens.txt` и ошибок в `output/errors.txt`.
12. **Print tokens.txt** — вывод содержимого файла токенов на экран.
13. **Print errors.txt** — вывод содержимого файла ошибок сканирования на экран.
14. **Run Syntax Analyzer (LL(1))** — запуск синтаксического анализатора на списке полученных токенов. Проверяет грамматику и семантику файла, строит ПОЛИЗ и сохраняет в `output/poliz.txt` (трассировка шагов автомата записывается в `output/trace.txt`).
15. **Execute Program (Run VM)** — сквозной запуск: токенизация, синтаксический анализ, генерация ПОЛИЗа и его непосредственное выполнение на стековой виртуальной машине.

ЛЕКСИКА И ПРАВИЛА ВХОДНОГО ЯЗЫКА
Разрабатываемый язык поддерживает строго определенные лексические и синтаксические конструкции:
1. **Типы данных:**
   * `int` — целочисленный тип (32-битное знаковое целое число).
   * `float` — вещественный тип (число с плавающей точкой двойной точности).
   * `array<int>` — одномерный целочисленный массив фиксированного размера.
   * `array<float>` — одномерный массив вещественных чисел фиксированного размера.
2. **Зарезервированные слова (Ключевые слова):**
   * В языке зарезервировано два ключевых слова для объявления базовых типов данных: `int` и `float` (хранятся в `config/reserved_words.txt`).
3. **Правила идентификаторов (Переменных):**
   * Должны начинаться строго с латинской буквы или символа подчеркивания `_`.
   * Могут содержать латинские буквы (в любом регистре), цифры и символ подчеркивания `_`.
   * Язык регистрозависим (например, `myVar`, `MyVar` и `MYVAR` будут распознаны как абсолютно разные идентификаторы).
   * Имя идентификатора не должно быть зарезервированным ключевым словом.
4. **Правила записи констант:**
   * **Именованные константы** (`NAMED_CONSTANT`) — идентификаторы, имена которых состоят строго из заглавных латинских букв и символов `_` (например, `MAX_VALUE`, `PI`). После первого присваивания (инициализации при объявлении) повторное присваивание значения блокируется семантическим анализатором.
   * **Неименованные константы** (`UNNAMED_CONSTANT`) — числовые константы. Целые числа (например, `42`, `0`, `5`) или вещественные с обязательной точкой в качестве разделителя дробной части (например, `15.5`, `3.14`, `1.1`).
5. **Массивы:**
   * Объявление одномерного массива происходит с указанием размера в квадратных скобках (размер должен быть строго целой неименованной константой): `int my_arr[4];` или `float f_arr[10];`.
   * Инициализация или групповое присваивание элементов массива выполняется списком констант в квадратных скобках через запятую: `my_arr = [10, 20, 30, 40];`.
   * Доступ к отдельному элементу (чтение и запись) происходит по индексу в квадратных скобках: `my_arr[2] = my_arr[1] * 5;`.
6. **Комментарии:**
   * Однострочные комментарии начинаются с символов `//` и действуют до конца текущей строки.
   * Многострочные комментарии заключаются в границы `/*` и `*/`. Сканер контролирует закрытие комментариев и выдает ошибку, если конец файла достигнут до закрытия комментария.

СЕМАНТИЧЕСКИЙ АНАЛИЗ (Semantic Checks)
В данной работе **семантический анализ полностью интегрирован в синтаксический анализатор и выполняется непосредственно синтаксическим анализатором (`SyntaxAnalyzer`)** в процессе разбора токенов. 
Анализатор проводит глубокие семантические проверки как во время предварительного обхода последовательности токенов, так и в процессе выполнения переходов управляющего автомата:
1. **Повторное объявление переменных:** Контролирует, чтобы одна и та же переменная не объявлялась дважды в одной области видимости (генерирует ошибку `Redeclaration of variable '...'`).
2. **Использование необъявленных переменных:** Запрещает операции присваивания или использование в выражениях переменных, которые не были объявлены ранее с типом `int` или `float` (генерирует ошибку `Assignment to undeclared variable '...'`).
3. **Модификация именованных констант:** Предотвращает попытки повторного присваивания значений именованным константам (полностью заглавные буквы) после их инициализации при объявлении (ошибка `Reassignment of named constant '...'`).
4. **Совместимость типов данных:** Запрещает присваивать вещественные значения (`float`) переменным целого типа (`int`), предотвращая неявную потерю точности (ошибка `Type mismatch, cannot assign float to int`).
5. **Размерность массивов при объявлении:** Проверяет, чтобы размер массива при описании был задан строго целочисленной константой (ошибка `Array size must be an integer` при попытке объявить `int arr[4.5];`).

ИСПОЛНЕНИЕ НА ВИРТУАЛЬНОЙ МАШИНЕ (ПОЛИЗ)
После успешного синтаксического и семантического анализа программа переводится в **ПОЛИЗ** (инфиксное выражение `a = b + c` преобразуется в постфиксную форму `a b c + =`).
Виртуальная машина (`interpreter.cpp`) выполняет ПОЛИЗ на основе стека операндов.

1. **Основные поддерживаемые операции:**
   * Арифметические операции: сложение `+`, вычитание `-`, умножение `*`.
   * Операции сравнения: равенство `==`, неравенство `!=`, меньше `<`, больше `>`.
   * Оператор присваивания `=`.
   * Оператор доступа к элементу массива **`АЭМ`** (Адресный Элемент Массива): выталкивает из стека индекс и имя массива, проверяет валидность и кладет значение элемента на вершину стека.

2. **Динамические проверки (Runtime Checks) виртуальной машины:**
   * **Выход за границы массива:** При выполнении операции `АЭМ` проверяет, чтобы вычисленный индекс элемента был строго в пределах `[0; array_size - 1]`. При нарушении выбрасывается исключение `Runtime Error: Array index out of bounds`.
   * **Использование неинициализированных переменных:** Если переменная используется в выражении, но не имеет заданного значения (значение равно `"-"`), генерируется ошибка `Runtime Error: Uninitialized variable '...'`.
   * **Переполнение целочисленных типов (Integer Overflow):** При выполнении арифметических операций (`+`, `-`, `*`) над операндами типа `int` виртуальная машина проверяет выход за границы стандартного 32-битного знакового целого `[INT_MIN, INT_MAX]`. При превышении генерируется ошибка переполнения (например, `Runtime Error: Integer Overflow (*)`).
   * **Недостаток операндов в стеке:** Защита от сбоя стека (исключение `Runtime Error: Stack underflow`).
